# Loss composition and epitope-site enforcement in AlphaFold-backpropagation / hallucination binder-design pipelines

Scope note: all code-level claims below were read directly from the named source files (fetched 2026-10-05 from the repositories' `main` branches). Paper-level claims are attributed to the paper URL. Where a claim came from a model-summarized fetch of a long paper rather than from code I read line-by-line, it is marked **[summarized]**.

## ColabDesign / AfDesign binder hallucination: what site-targeting loss options exist, exact names and defaults

### Takeaway
AfDesign's only site-targeting mechanism is `opt["hotspot"]`, which does not add a term — it **swaps the mask roles inside the existing `i_con` interface-contact loss** so the reduction runs over hotspot residues instead of binder residues. There is no epitope-specific PAE/pTM term, no center-of-mass term, and no off-epitope penalty anywhere in the library.

### Cited Findings
- `_loss_binder` in `colabdesign/af/loss.py` (L34–81) computes exactly six unsupervised terms: `plddt`, `exp_res`, `pae`, `con`, `i_con`, `i_pae` — [ColabDesign af/loss.py](https://github.com/sokrypton/ColabDesign/blob/main/colabdesign/af/loss.py)
- The hotspot branch (L42–47) is a **mask role swap**, not an extra term:
  ```python
  binder_id = zeros.at[-bL:].set(mask[-bL:])
  if "hotspot" in opt:
    target_id  = zeros.at[opt["hotspot"]].set(mask[opt["hotspot"]])
    i_con_loss = get_con_loss(inputs, outputs, opt["i_con"], mask_1d=target_id, mask_1b=binder_id)
  else:
    target_id  = zeros.at[:tL].set(mask[:tL])
    i_con_loss = get_con_loss(inputs, outputs, opt["i_con"], mask_1d=binder_id, mask_1b=target_id)
  ```
  With a hotspot, `mask_1d` (rows, reduced by `num_pos`) = hotspot residues and `mask_1b` (columns, reduced by `num`) = binder. Without one, rows = binder residues. — [ColabDesign af/loss.py L42–47](https://github.com/sokrypton/ColabDesign/blob/main/colabdesign/af/loss.py)
- `i_pae` is **never** hotspot-masked: `"i_pae": get_pae_loss(outputs, mask_1d=binder_id, mask_1b=target_id)` uses `target_id`, which is the hotspot set only because the hotspot branch rebinds `target_id`. In the no-hotspot branch `target_id` is the whole target. So when a hotspot IS given, `i_pae` is incidentally restricted to binder×hotspot pairs; this is a side effect of variable reuse, not a documented option. — [ColabDesign af/loss.py L48–58](https://github.com/sokrypton/ColabDesign/blob/main/colabdesign/af/loss.py)
- `get_con_loss` (L261–297) functional form:
  ```python
  p = _get_con_loss(dgram, dgram_bins, cutoff=con_opt["cutoff"], binary=con_opt["binary"])  # [L,L]
  m = (|offset| >= con_opt["seqsep"]) if "seqsep" in con_opt else ones
  m = logical_and(m, mask_1b)
  p = min_k(p, con_opt["num"],     m)        # per row: mean of the `num` SMALLEST values over allowed cols
  return min_k(p, con_opt["num_pos"], mask_1d) # mean of the `num_pos` SMALLEST row values over allowed rows
  ```
  `min_k(x,k,mask)` sorts, keeps the k smallest non-NaN entries, returns their mean. — [ColabDesign af/loss.py L261–297](https://github.com/sokrypton/ColabDesign/blob/main/colabdesign/af/loss.py)
- `_get_con_loss` (L299–308): `bins = dgram_bins < cutoff`; `binary=True` → `-log((bins*softmax(dgram)).sum(-1))` i.e. negative log-probability of distance below cutoff; `binary=False` → categorical cross-entropy `-(px_ * log_softmax(dgram)).sum(-1)` where `px_ = softmax(dgram - 1e7*(1-bins))` is the distogram renormalized onto sub-cutoff bins. — [ColabDesign af/loss.py L299–308](https://github.com/sokrypton/ColabDesign/blob/main/colabdesign/af/loss.py)
- `get_pae_loss` (L251–259): `p = PAE/31.0`, symmetrized `(p+p.T)/2`, then masked mean over `mask_2d * mask_1d[:,None] * mask_1b[None,:]`. — [ColabDesign af/loss.py L251–259](https://github.com/sokrypton/ColabDesign/blob/main/colabdesign/af/loss.py)
- Option defaults, `colabdesign/af/model.py` L50–51:
  ```python
  "con":   {"num":2, "cutoff":14.0,    "binary":False, "seqsep":9, "num_pos":float("inf")}
  "i_con": {"num":1, "cutoff":21.6875, "binary":False,             "num_pos":float("inf")}
  ```
  (21.6875 Å is the last distogram bin edge, i.e. effectively no distance restriction.) Base weights L53: `{"seq_ent":0.0,"plddt":0.0,"pae":0.0,"exp_res":0.0,"helix":0.0}`. — [ColabDesign af/model.py L50–53](https://github.com/sokrypton/ColabDesign/blob/main/colabdesign/af/model.py)
- Binder-hallucination default weights, `colabdesign/af/prep.py` L240: `{"plddt":0.1, "con":0.0, "i_con":1.0, "i_pae":0.0}`. Binder-**redesign** (template present) default weights, L235–236: `{"dgram_cce":1.0,"rmsd":0.0,"fape":0.0,"con":0.0,"i_con":0.0,"i_pae":0.0}` — i.e. in redesign mode the interface terms are **off by default**. — [ColabDesign af/prep.py](https://github.com/sokrypton/ColabDesign/blob/main/colabdesign/af/prep.py)
- Hotspot parsing, `prep.py` L229–230: `self.opt["hotspot"] = prep_pos(hotspot, **self._pdb["idx"])["pos"]` (accepts `"A54,A56,A66-70"`-style strings). — [ColabDesign af/prep.py L229](https://github.com/sokrypton/ColabDesign/blob/main/colabdesign/af/prep.py)

### Inferences
- `num_pos` is the single most important and most overlooked knob for site enforcement. With `num_pos = inf` (the default) the loss averages over **all** hotspot rows, so every hotspot residue must acquire `num` binder contacts — nominally strict. But because the reduction is `min_k` over the *smallest* (i.e. best-satisfied) values and `cutoff` is large, the term is cheaply satisfied by a binder that merely sits in the general vicinity. Setting `num_pos = k < |hotspot|` makes it *looser* (only k hotspots need engagement), which is the opposite of what one might assume.
- Because the contact term is a distogram cross-entropy at a 14–22 Å cutoff, it is a **proximity** term, not a docking term. Nothing in AfDesign penalizes contacts made *outside* the hotspot set. A binder can fully satisfy `i_con` while burying most of its surface on a neighbouring patch — which is exactly the 14–27 Å off-epitope failure mode described in the user's project.

### Gaps
- There is no `i_pdae`/`i_pDAE`, center-of-mass, or off-epitope-repulsion term in upstream ColabDesign; those exist only in downstream forks (BindCraft2, Germinal).

## BindCraft (Pacesa et al., Nature 2025) and BindCraft2: full loss composition, how the site is specified, and whether it is a loss, a filter, or both

### Takeaway
In **BindCraft 1** the epitope enters **only** the gradient (via AfDesign's hotspot mask on `i_con`), and the one filter whose name suggests site checking — `Hotspot_RMSD` — does **not** measure distance to the specified epitope; it measures whether the ProteinMPNN-redesigned sequence re-predicts into the same pose as its own hallucinated trajectory. **BindCraft 2** closes this gap: it adds site-specific *filter* metrics (`Hotspot_Contact_Fraction`, `Epitope_Residues_Contacted`, `Off_Epitope_Contact_Fraction`, `Coldspot_Contact_Fraction`) and a `forced_targeting` mode that manipulates the target template rather than the loss.

### Cited Findings — BindCraft 1 gradient-time loss (code)
- Loss wiring, `functions/colabdesign_utils.py` L40–49:
  ```python
  af_model.opt["weights"].update({"pae": weights_pae_intra, "plddt": weights_plddt,
                                  "i_pae": weights_pae_inter, "con": weights_con_intra,
                                  "i_con": weights_con_inter})
  af_model.opt["con"].update({"num":intra_contact_number, "cutoff":intra_contact_distance,
                              "binary":False, "seqsep":9})
  af_model.opt["i_con"].update({"num":inter_contact_number, "cutoff":inter_contact_distance,
                                "binary":False})
  ```
  Note `num_pos` is **not** set, so it stays at ColabDesign's `inf`. — [BindCraft functions/colabdesign_utils.py](https://github.com/martinpacesa/BindCraft/blob/main/functions/colabdesign_utils.py)
- Default weights, `settings_advanced/default_4stage_multimer.json`: `weights_plddt 0.1`, `weights_pae_intra 0.4`, `weights_pae_inter 0.1`, `weights_con_intra 1.0`, `weights_con_inter 1.0`, `intra_contact_distance 14.0`, `inter_contact_distance 20.0`, `intra_contact_number 2`, `inter_contact_number 2`, `weights_helicity -0.3`, `weights_iptm 0.05` (`use_i_ptm_loss: true`), `weights_rg 0.3` (`use_rg_loss: true`), `weights_termini_loss 0.1` (`use_termini_distance_loss: false`). — [BindCraft default_4stage_multimer.json](https://github.com/martinpacesa/BindCraft/blob/main/settings_advanced/default_4stage_multimer.json)
- Extra terms added on top of AfDesign, same file: `add_rg_loss` (L375), `add_i_ptm_loss` (L391), `add_helix_loss` (L401, penalizes/rewards i,i+3 contacts at 6.0 Å cutoff), `add_termini_distance_loss` (L431, `threshold_distance=7.0`). — [BindCraft functions/colabdesign_utils.py L375–456](https://github.com/martinpacesa/BindCraft/blob/main/functions/colabdesign_utils.py)
- Paper's own enumeration of the eight-term design loss with weights: binder pLDDT (0.1), interface i_pTM (0.05), normalized pAE within binder (0.4), normalized pAE binder↔target (0.1), contact loss within binder (1.0), contact loss binder↔target (1.0), radius of gyration (0.3), helicity (−0.3) — matches the JSON exactly. **[summarized]** — [BindCraft preprint, full text](https://www.biorxiv.org/content/10.1101/2024.09.30.615802v1.full)

- 4-stage schedule (`colabdesign_utils.py` L100–160): `design_logits(iters=50, e_soft=0.9)` → gate on best-iteration binder pLDDT > 0.65 → additional `design_logits(iters = soft_iterations−50 = 25, e_soft=1)` → `design_soft(45, e_temp=1e-2)` → gate pLDDT > 0.65 → `design_hard(5, temp=1e-2, dropout=False)` → gate pLDDT > 0.65 → `design_pssm_semigreedy(soft_iters=0, hard_iters=15, tries=ceil(L·1%))`. Optional beta-sheet detection (>15 % β) extends soft/temp iterations and raises recycles. — [BindCraft functions/colabdesign_utils.py](https://github.com/martinpacesa/BindCraft/blob/main/functions/colabdesign_utils.py)
- Post-trajectory gates, same file L180–210: CA-clash count at 2.5 Å must be 0; final best-loss pLDDT ≥ 0.7; `len(hotspot_residues(model_pdb_path)) >= 3` where `hotspot_residues(pdb, binder_chain="B", atom_distance_cutoff=4.0)` just counts **any** binder residue within 4.0 Å of **any** chain-A target atom. **None of these three gates reference the user-specified epitope.** — [BindCraft functions/colabdesign_utils.py](https://github.com/martinpacesa/BindCraft/blob/main/functions/colabdesign_utils.py); [functions/biopython_utils.py L138](https://github.com/martinpacesa/BindCraft/blob/main/functions/biopython_utils.py)

### Cited Findings — BindCraft 1 selection stage (the crux)
- `bindcraft.py` L264: `rmsd_site = unaligned_rmsd(trajectory_pdb, mpnn_design_pdb, binder_chain, binder_chain)`; L296: `'Hotspot_RMSD': rmsd_site`. — [BindCraft bindcraft.py](https://github.com/martinpacesa/BindCraft/blob/main/bindcraft.py)

The repo JSON is authoritative for the code; the paper's list is the narrative description.

### Cited Findings — reported rate of binding the specified hotspots
- The BindCraft paper provides **no aggregate statistic** for the fraction of designs that bind at the intended site. Site accuracy is argued from structures and competition assays: crystal structures BBF-14/binder4 (backbone RMSD 1.7 Å), Der f7/binder2 (1.7 Å), Der f21/binder10 (3.1 Å); cryo-EM of SpCas9/binder3 and SpCas9/binder10 with "clear density in the binding pocket"; competition assays showing epitope overlap with IFNAR2 for the IFNA2 binder and with pembrolizumab for the PD-1 binder. **[summarized]** — [BindCraft preprint](https://www.biorxiv.org/content/10.1101/2024.09.30.615802v1.full)
- Per-target experimental success rates (designs tested → confirmed binders): PD-1 53→13; PD-L1 9→7; IFNAR2 9→3; CD45 16→4; BBF-14 11→6; SAS-6 9→1; Der f7 10→4; Der f21 7→4; Bet v1 7→2; SpCas9 6→6 — summarized as an average ~49.5 %, range 10–100 %. **[summarized, from the v1 preprint; the Nature 2025 version may differ]** — [BindCraft preprint](https://www.biorxiv.org/content/10.1101/2024.09.30.615802v1.full)

### Cited Findings — BindCraft2
- Loss setting names and defaults: `weights_plddt_loss 0.1`, `weights_binder_pae 0.4`, `weights_interface_pae 0.1`, `weights_compactness 0.5`, `weights_iptm_loss 0.05`, `weights_interface_contacts 1.0`, `weights_binder_contacts 1.0`, `weights_binder_helicity -0.3`. **[summarized]** — [BindCraft2 docs/source/reference.md](https://github.com/PacesaLab/BindCraft2/blob/main/docs/source/reference.md)
- Off-by-default (null/0) weights that are directly relevant to site control: `weights_binder_coldspot`, `weights_binder_intra_coldspot`, `weights_binder_intra_hotspot`, `weights_coldspot_repel`, `weights_non_contact`, `weights_com_distance`, `weights_target_rmsd`, `weights_target_rigidity`, `weights_distogram_cce`, `weights_ptm_loss`, plus induced-fit, fold-switching, multidomain and termini terms. **[summarized]** — [BindCraft2 reference.md](https://github.com/PacesaLab/BindCraft2/blob/main/docs/source/reference.md)
- Hotspot syntax: `"hotspots": "54,56,66-70"` inside the target entry, chain-prefixed for multi-chain (`"A54,B12-16"`). Coldspots: `coldspots` entry "automatically add repulsion and a default contact ceiling of 0.05." **[summarized]** — [BindCraft2 reference.md](https://github.com/PacesaLab/BindCraft2/blob/main/docs/source/reference.md)
- `forced_targeting` semantics: "During early design it replaces exposed residues outside the protected hotspot shell with lysine, then restores the original target before hardening and validation." Requires a structured target, `hotspots`, and `forced_targeting_shell` (default **10 Å**). So it is **template manipulation during screening/refinement, not a loss term and not a filter**; ordinary hotspots do not require it. **[summarized]** — [BindCraft2 reference.md](https://github.com/PacesaLab/BindCraft2/blob/main/docs/source/reference.md)
- BindCraft2 **site-specific filter shortcuts** (the thing BindCraft 1 lacks): `min_hotspot_contact_final` → `Hotspot_Contact_Fraction`; `max_coldspot_contact_final` → `Coldspot_Contact_Fraction`; `min_epitope_residues_contacted_final` → `Epitope_Residues_Contacted`; `max_off_epitope_contact_final` → `Off_Epitope_Contact_Fraction`. Antibody-specific analogues: `max_off_paratope_contact_final` → `Off_Paratope_Contact_Fraction`; `min_framework_packing_final` → `Framework_Packing_Fraction`. Scaffold-retention: `max_scaffold_framework_rmsd_final` → `Scaffold_Framework_RMSD`. **[summarized]** — [BindCraft2 reference.md](https://github.com/PacesaLab/BindCraft2/blob/main/docs/source/reference.md)
- BindCraft2 standard (non-site) filters: free-binder pLDDT 0.7; complex pTM 0.55; normalized i_pAE ≤ 0.35; interface residues ≥ 7; no backbone clashes. Stage-wise pLDDT floors 0.6 (screen/refine/mutate), 0.65 (anneal/harden), 0.7 (final). i_pTM unset at screen/refine, 0.5 at anneal/harden/mutate, 0.7 final. Off-target: `max_detarget_interface_residues_final` 3. **[summarized]** — [BindCraft2 reference.md](https://github.com/PacesaLab/BindCraft2/blob/main/docs/source/reference.md)
- Ranking: candidates are ranked by **`i_pDAE`** ("Retain the best passing candidates by `i_pDAE`", `kept_sequences: 1` default); `bindcraft rank` can re-rank by `i_pTM`. — [BindCraft2 reference.md](https://github.com/PacesaLab/BindCraft2/blob/main/docs/source/reference.md); [BindCraft2 repo](https://github.com/PacesaLab/BindCraft2)

### Inferences
- The `Hotspot_RMSD` name in BindCraft 1 is actively misleading and is a plausible source of the belief that BindCraft filters on epitope. Mechanically: `trajectory_pdb` and `mpnn_design_pdb` are both AF2 complex predictions built on the same target template, so their target chains occupy approximately the same frame; the un-superposed binder-chain RMSD therefore measures *whether MPNN redesign preserved the hallucinated pose*, i.e. trajectory→MPNN self-consistency. If the trajectory itself docked off-epitope, `Hotspot_RMSD ≤ 6 Å` **rewards** faithfully reproducing the wrong site.
- BindCraft 1's selection stage is thus entirely site-agnostic (i_pTM, i_pAE, pLDDT, SC, ΔG, interface residues, hydrophobicity) — structurally the same gap the user describes. BindCraft2's `Off_Epitope_Contact_Fraction` / `Epitope_Residues_Contacted` are the direct fix.
- `forced_targeting` is worth noting as an alternative strategy to loss shaping: lysine-scanning the solvent-exposed target surface *outside* a 10 Å shell around the hotspots makes off-epitope docking energetically/confidence-wise unattractive to the frozen predictor itself, without touching the loss weights. For a frozen AF3-like predictor with sequence gradients this is directly transferable (it is an input-space intervention, not a loss-space one).

### Gaps
- `i_pDAE`'s exact definition is not given in BindCraft2's `reference.md`; it is described as a distance-masked interface confidence score and the full definition is deferred to `docs/source/outputs.md`, which I did not fetch. Whether the distance mask is epitope-aware is therefore **unresolved** — if it is, BindCraft2's *ranking* metric would itself be site-aware, which would be highly relevant to the user.
- Default numeric thresholds for the BindCraft2 site filters (e.g. what `min_hotspot_contact_final` defaults to) were not recovered; the docs list them as shortcuts, and several off-target filters are explicitly "Unset by default."
- I could not confirm the final Nature 2025 per-target success numbers; the table above is from the bioRxiv v1 full text.

## Germinal (Nature Biotechnology 2026): epitope targeting, loss terms, LM/structure-predictor gradient merging, off-epitope reporting

### Takeaway
Germinal is the most relevant precedent: it keeps the AfDesign hotspot mask in the gradient **and** adds hard site-specific booleans to **both** filtering stages — `binder_near_hotspot == true`, `cdr3_hotspot_contacts > 0`, `percent_interface_cdr ≥ 0.5` — computed geometrically from the predicted complex at a 5.3 Å / 6.0 Å / ≥3-contact definition. It also introduces a signed paratope loss `L_CDR − λ·L_framework` that penalizes contacts made by the *wrong part of the binder*.

### Cited Findings — epitope specification and gradient-time losses
- Hotspots come from the target settings file and are passed straight through: `hotspot = target_settings.get("target_hotspots", "")` → `prep_inputs(..., hotspot=target_hotspot_residues)`, i.e. the same `opt["hotspot"]` mask-swap mechanism as AfDesign. The paper describes `target_id` as "all specified hotspot residues on the target (or all residues in the target if no hotspot is specified)." **[summarized]** — [germinal/design/design.py](https://github.com/SantiagoMille/germinal/blob/main/germinal/design/design.py); [Germinal preprint v3 full text](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full)
- Weight dict actually set in code:
  ```python
  af_model.opt["weights"].update({"pae": weights_pae_intra, "i_plddt": weights_i_plddt,
      "plddt": weights_plddt, "i_pae": weights_pae_inter, "con": weights_con_intra,
      "i_con": weights_con_inter, "dgram_cce": run_settings.get("dgram_cce", 0.01)})
  af_model.opt["i_con"].update({"num": inter_contact_number, "cutoff": inter_contact_distance,
      "binary": False, "framework_contact_loss": framework_contact_loss,
      "framework_contact_offset": framework_contact_offset})
  ```
  — [germinal/design/design.py](https://github.com/SantiagoMille/germinal/blob/main/germinal/design/design.py)
- `configs/run/vhh.yaml` values: pLDDT **1.0**, interface pLDDT **1.0**, pae_intra **0.1**, pae_inter **0.5**, ipTM **0.75**, con_intra **0.1**, con_inter **0.2**, radius of gyration **0.1**, helix **0.1**, beta **0.2**; `intra_contact_distance 14.0`, `inter_contact_distance 20.0`, `intra_contact_number 2`, **`inter_contact_number 10`**; framework contact loss enabled with offset 1. — [germinal configs/run/vhh.yaml](https://github.com/SantiagoMille/germinal/blob/main/configs/run/vhh.yaml)
- Paratope loss: `L_CDR` is a categorical cross-entropy on distogram distance probabilities with a user-defined distance threshold, between CDR positions (`pos_id`) and target epitope residues; `L_framework` is the identical CCE between framework residues (`fw_id`) and **all** target residues; combined as **`L_paratope ∝ L_CDR − λ·L_framework`** with user-defined λ. **[summarized]** — [Germinal preprint v3](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full)
- CDR secondary-structure losses: α-helix loss penalizes CDR {i, i+3} pairs whose predicted distance falls in **2–6.2 Å** (binary cross-entropy on the distogram with a positional mask restricting evaluation to CDR residues); β-strand loss penalizes {i, i+3} pairs in **9.75–11.5 Å**, applied to CDR positions "including the position directly before and directly after each CDR," averaging the "top three most likely pairs." Code exposes `add_helix_loss`, `add_beta_strand_loss`, and `add_beta_sheet_loss(af_model, cdr_lengths, beta_strand_weight)` (4.4–6.0 Å for CDR regions). **[summarized + code]** — [Germinal preprint v3](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full); [germinal/design/design.py](https://github.com/SantiagoMille/germinal/blob/main/germinal/design/design.py)
- Full ColabDesign-derived term list used: pLDDT, ipLDDT, iPAE, PAE, ipTM, pTM, inter-protein contacts (user-specified number and distance), intra-protein contacts (minimum contact count). No radius-of-gyration term is described in the paper text, though `weights_rg: 0.1` appears in the VHH config. **[summarized]** — [Germinal preprint v3](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full)

### Cited Findings — multi-objective gradient merging
- Three merge strategies implemented: **Weighted Sum** ("AF-M weight is fixed to 1, and the IgLM weight λ is set by a user-defined parameter"); **PCGrad (weighted)** — one gradient "projected onto the orthogonal complement of the other if the dot product is negative, thereby preventing cancellation"; **MGDA** — solves for a "convex combination of AF-M and IgLM gradients that minimizes the squared norm of the merged update." **[summarized]** — [Germinal preprint v3](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full)
- Gradient-norm balancing: "Gradients from both models are normalized to their respective ℓ2-norms" before merging, and re-normalized after combination. **[summarized]** — [Germinal preprint v3](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full)
- LM weight annealing: a four-step schedule — linearly annealed during the logits→softmax phase, then fixed through the softmax and semi-greedy phases. In code: `ablm_scale = run_settings.get("ablm_scale", [0.0, 0.2, 0.4, 1.0])`; `configs/run/vhh.yaml` uses `[0.2, 0.4, 0.4, 1.0]` with PCGrad, LM temperature 0.6 and bias-redesign strength 10. **[summarized + code]** — [Germinal preprint v3](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full); [germinal configs/run/vhh.yaml](https://github.com/SantiagoMille/germinal/blob/main/configs/run/vhh.yaml)
- Staged loop: `design_logits(logits_steps=65)` → `design_soft(softmax_steps=35)` → `design_pssm_semigreedy(hard_iters=search_steps=10, mutation rate 0.05)`; in-run save/advance gates `save_filters = {"plddt": 0.84, "i_ptm": 0.65, "i_pae": 0.3}` in code, with `configs/run/vhh.yaml` specifying pLDDT 0.82 / ipTM 0.68 / PAE 0.27. Paper reports design-stage thresholds pLDDT > 0.8, ipTM > 0.68, iPAE < 0.35. **[summarized + code]** — [germinal/design/design.py](https://github.com/SantiagoMille/germinal/blob/main/germinal/design/design.py); [germinal configs/run/vhh.yaml](https://github.com/SantiagoMille/germinal/blob/main/configs/run/vhh.yaml); [Germinal preprint v3](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full)

### Cited Findings — site-specific SELECTION (the direct answer to the user's gap)
- `configs/filter/initial/vhh.yaml` ("more lenient filters applied after the hallucination step") contains exactly five filters: `clashes < 1`; **`binder_near_hotspot == true`**; **`cdr3_hotspot_contacts > 0`**; **`percent_interface_cdr > 0.5`**; `interface_shape_comp > 0.6`. Three of the five are site/paratope-specific, and there is **no confidence metric at all** in the initial filter. — [germinal configs/filter/initial/vhh.yaml](https://github.com/SantiagoMille/germinal/blob/main/configs/filter/initial/vhh.yaml)
- `configs/filter/final/vhh.yaml`: `clashes < 1`; `sc_rmsd < 6.0`; **`binder_near_hotspot == true`**; **`cdr3_hotspot_contacts > 0`**; **`percent_interface_cdr ≥ 0.5`**; `interface_shape_comp ≥ 0.6`; `interface_hbonds ≥ 3`; `surface_hydrophobicity ≤ 0.4`; `interface_hydrophobicity ≥ 45`; `pdockq2 > 0.23`; `external_plddt > 0.87`; `external_iptm > 0.74`; `external_ptm > 0.84`; `external_pae < 7.5`. — [germinal configs/filter/final/vhh.yaml](https://github.com/SantiagoMille/germinal/blob/main/configs/filter/final/vhh.yaml)

### Cited Findings — off-epitope / off-paratope behaviour and validation
- Reported failure mode: "a subset of designs was observed to engage the target through secondary-structure-rich contacts. Interestingly, some of these designs tended to exhibit stronger binding affinities, but also showed higher signal in the polyspecificity assay." **[summarized]** — [Germinal preprint v3](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full)
- Epitope engagement validated by alanine mutagenesis at the computationally specified hotspots: binding reduced in **17 of 26 designs**, with at least one mutation abrogating binding entirely; control binders directed at different epitopes retained wild-type-like affinity for ≥1 variant. **[summarized]** — [Germinal preprint v3](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full)
- Cryo-EM of anti-PD-L1 scFv H5: global Cα RMSD **1.25 Å** versus the predicted model, with "contacts to the targeted hotspot residues (I37, Y39, E41) maintained as designed." **[summarized]** — [Germinal preprint v3](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full)
- Experimental throughput and hit rates (designs ordered → screened → confirmed): PD-L1 nanobody 101 → 25 screened → 7 BLI-confirmed, best K_D 170 nM; PD-L1 scFv 48 → 4 SPR hits → 3 confirmed, ~40–60 nM; IL3 nanobody 46 → 11 → 2, 280 nM; IL3 scFv 48 → 1 SPR hit → 1, ~60–70 nM; IL20 nanobody 43 → 11 → 4, 190 nM; BHRF1 nanobody 52 → 20 → 5, 1.2 µM. Headline: **4–22 % experimental success across four targets, testing only 43–101 designs per antigen.** **[summarized]** — [Germinal preprint v3](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full); [PubMed 41040335](https://pubmed.ncbi.nlm.nih.gov/41040335/); [PubMed 42337361 (Nat Biotechnol version)](https://pubmed.ncbi.nlm.nih.gov/42337361/)

### Inferences
- The structural pattern in Germinal is: **continuous, weak site pressure in the gradient; discrete, hard site gates in selection.** The gradient term is just AfDesign's hotspot-masked `i_con` at a 20 Å cutoff (with `inter_contact_number` raised to 10, which demands more binder partners per hotspot but still at 20 Å) — the same weak pressure the user already has. What differs is that `binder_near_hotspot` is a **boolean pass/fail at 5.3 Å with ≥3 CDR contacts**, applied *before* any confidence metric is consulted in the initial filter. A design 14–27 Å off-epitope fails this immediately regardless of ipTM/ipSAE.
- Germinal computes `ipsae` but does **not** list it among the VHH filter thresholds — it relies on `pdockq2`, `external_iptm`, etc. for confidence, and on the hotspot booleans for site. This is evidence that the authors treated confidence and site as *separate, non-substitutable* axes, which is precisely the diagnosis for the user's pipeline (ipSAE 0.77 with a 14–27 Å offset is not a contradiction — it is the expected outcome of ranking on a site-agnostic metric).
- `L_paratope ∝ L_CDR − λ·L_framework` is the only *negative* (repulsive) site term in any of these pipelines: the framework CCE is **subtracted**, i.e. framework-to-target proximity is actively penalized. The analogous construction for the user's problem is an off-epitope repulsion term — `L_contact(binder, epitope) − λ·L_contact(binder, non-epitope surface)` — which no other pipeline surveyed implements at gradient time (BindCraft2 does it only as a filter, via `Off_Epitope_Contact_Fraction`).

### Gaps
- Table S4 (Borda-count metric weights) was not recovered, so I cannot say how heavily the site metrics are weighted in the *ranking* (as opposed to the pass/fail filtering).
- The exact λ used for the paratope loss, and the `framework_contact_offset: 1` semantics, are not stated in the materials I retrieved.
- Germinal reports no quantitative "fraction of designs predicted off-epitope before filtering" — so the magnitude of the problem the filters are solving is not published.

## EasyNano (arXiv 2606.12772, 2026): exact objective terms, proxy/full-model divergence, pose dependence

### Takeaway
EasyNano is the only pipeline with an explicit, metric-space (not confidence-space) epitope-distance term: an ELU hinge on CDR→epitope expected Cβ distance with an 8 Å set-point, weighted 0.2 — plus a *pose prior* that pins the framework via a binary mask over the full-model distogram. Its central reported caveat is that the method cannot repair a wrong initial pose, and that the fast proxy diverges from the full model by up to 7 Å in CDR→epitope distance.

### Cited Findings
- Composite loss (Equation 1): **ℒ = w_epi·ℒ_epitope + w_intra·ℒ_intra + w_inter·ℒ_inter + w_glob·ℒ_glob + w_prior·ℒ_structure_prior + w_aa·ℒ_aa_freq**, with weights **[0.2, 0.5, 0.5, 0.2, 0.05, 0.01]**. **[summarized]** — [EasyNano arXiv HTML](https://arxiv.org/html/2606.12772v1)
- Epitope term: **ℒ_epitope = (1/|𝒞|) Σ_{i∈𝒞} ELU( min_{j∈ℰ} d̄_ij − 8.0 )**, where 𝒞 = CDR residues, ℰ = epitope residues, d̄ = expected Cβ distance from the distogram; i.e. an ELU-shaped penalty that activates only when the minimum CDR-to-epitope distance exceeds 8 Å. **[summarized]** — [EasyNano arXiv HTML](https://arxiv.org/html/2606.12772v1)
- Pose prior: the wild-type complex is folded once with **full ESMFold2 (1.3 B parameters, 3 recycling loops, 14 sampling steps, 4 diffusion samples)** to produce CA-coordinate distance priors that "anchor the framework pose during optimization." The prior is "a binary mask over a 64-bin distance distogram (2 Å to 22 Å) with 2.5 Å bin tolerance," weight 0.05. **[summarized]** — [EasyNano arXiv HTML](https://arxiv.org/html/2606.12772v1)
- Proxy/full divergence: "the Fast model's ipTM values are poorly calibrated (Fast-to-Full cdr→epitope discrepancies of up to 7 Å)"; the authors require post-hoc re-evaluation of top candidates with full ESMFold2, noting divergence is worst "for frameworks with poor initial poses." **[summarized]** — [EasyNano arXiv HTML](https://arxiv.org/html/2606.12772v1)
- Pose dependence: "if the framework's predicted pose is incorrect (as with anti-TNF, 44 Å from crystal), CDR optimization alone cannot compensate" — the anti-TNF case gained only **+0.024 ipTM** despite extensive CDR mutation. For the de novo AQP4 case, "the B5 nanobody framework (127 residues, framework III) was manually docked near the AQP4 extracellular loop C epitope using PyMOL to provide the initial pose for the structure prior." **[summarized]** — [EasyNano arXiv HTML](https://arxiv.org/html/2606.12772v1)
- Reported ipTM: Ty1/RBD 0.143 → 0.702 (+0.559, "5.7σ above random"); KN035/PD-L1 0.251 → 0.459 (+0.208, 2.2σ); AQP4 de novo 0.117 → 0.538 (4.6-fold; 0.692 after framework optimization); VHH72/RBD and VHH3/TNFα already-strong binders preserved at ipTM > 0.67. Runtime ~10–20 min on a high-end workstation. **[summarized]** — [EasyNano arXiv HTML](https://arxiv.org/html/2606.12772v1); [arXiv abstract](https://arxiv.org/abs/2606.12772)
- **No experimental validation**: "we have not yet experimentally validated designed sequences; binding must be confirmed by SPR or BLI." **[summarized]** — [EasyNano arXiv HTML](https://arxiv.org/html/2606.12772v1)
- The paper does not report cases of designed binders engaging an off-target epitope; the documented failure mode is instead inability to improve from a wrong starting pose. **[summarized]** — [EasyNano arXiv HTML](https://arxiv.org/html/2606.12772v1)

### Inferences
- The ELU hinge is functionally very different from a distogram cross-entropy contact loss: it is zero inside 8 Å and grows (approximately linearly, for the ELU's positive branch) outside it, measured in Ångströms on an expectation of the distogram rather than in nats on bin probabilities. That makes its scale interpretable and its gradient non-vanishing at large separation — a candidate replacement for a `i_con`-style term when the current failure is a 14–27 Å offset, where a 20 Å-cutoff contact CCE is already near-saturated and uninformative.
- EasyNano's pose prior is a *restraint toward a specified pose*, not merely a specification of which residues should touch. Combined with the anti-TNF result, the paper's implicit thesis is that epitope specification via a distance loss is insufficient without a pose anchor — consistent with the user's observation that a coordinate pose-RMSD term plus a contact term still leaves a 14–27 Å offset, if the pose term is weak relative to the confidence terms.
- The acknowledged 7 Å Fast-vs-Full CDR→epitope discrepancy is a direct warning that site metrics should be recomputed on the full/expensive predictor at selection time, not read off the differentiable proxy used for the gradient.

### Gaps
- Functional forms of ℒ_intra, ℒ_inter, ℒ_glob and ℒ_aa_freq are not given in the paper (only their weights), so these cannot be reimplemented exactly.
- EasyNano is an arXiv preprint (submitted 11 June 2026) with no peer review and no wet-lab data; all reported gains are self-reported ipTM deltas on 6 target–framework pairs.

## BindEnergyCraft (arXiv 2505.21241): pTMEnergy as an ipTM replacement — does it address site specificity?

### Takeaway
No. BindEnergyCraft is purely about gradient density: it swaps ipTM for an energy-based LogSumExp over the pAE logits so gradients flow through all interface pairs rather than one argmax position. Its benchmarks were explicitly run "without applying any hotspot constraints," and the loss contains no site term.

### Cited Findings
- pTMEnergy (Equation 8): **E_pTMEnergy(x) = −(1/|ℐ|) Σ_{(i,j)∈ℐ} log Σ_{b=1}^{B} g(d_b) · exp ℓ_ijb**, where ℓ_ij are AlphaFold2's predicted-aligned-error logits over B distance bins for pair (i,j), g(d_b) is "the scaling kernel" that "up-weights the contributions of low alignment errors," and ℐ is the set of **inter-chain** residue pairs. Framed within Joint Energy-based Modeling (JEM). **[summarized]** — [BindEnergyCraft arXiv HTML](https://arxiv.org/html/2505.21241v1); [abstract](https://arxiv.org/abs/2505.21241)
- Contrast with ipTM: ipTM is `max_i [ (1/N) Σ_j E[g(e_ij)] ]`; the paper's Figure 3 shows ipTM "zeroes out the gradient from all but one position," while pTMEnergy "preserves gradients across the interface," producing "denser, more informative gradients." **[summarized]** — [BindEnergyCraft arXiv HTML](https://arxiv.org/html/2505.21241v1)
- Full loss (Algorithm 1): **ℒ = 0.05·E + 0.1·(1−pLDDT) + 0.1·ipAE + 0.4·pAE − con_inter − con_intra + 0.3·rad_gyr** — i.e. BindCraft's weights with pTMEnergy substituted at the ipTM slot's 0.05 weight. **[summarized]** — [BindEnergyCraft arXiv HTML](https://arxiv.org/html/2505.21241v1)
- Site specificity: "For every target, we generate 100 binder sequences... without applying any hotspot constraints." No loss term specifies a binding site or epitope. **[summarized]** — [BindEnergyCraft arXiv HTML](https://arxiv.org/html/2505.21241v1)
- Benchmarks (Table 1, in-silico success under Rosetta constraints): H3 32 % vs BindCraft 16 %; IL-2Rα 47 % vs 38 %; TrkA 36 % vs 29 %; best on 7/8 targets, gains up to 16 percentage points. Under folding-model constraints, best on 7/8 targets, +2 to +15 points. Table 2: clash rate reduced on all targets (e.g. ALK 22 % → 7 %). Virtual screening: miniprotein AUPRC 0.467 vs ipTM 0.434, Precision@5 0.675 vs 0.550; RNA aptamers AUPRC 0.352, Precision@10 0.400. **[summarized]** — [BindEnergyCraft arXiv HTML](https://arxiv.org/html/2505.21241v1)
- Validation status: "our current results are purely computational, and experimental validation is necessary." **[summarized]** — [BindEnergyCraft arXiv HTML](https://arxiv.org/html/2505.21241v1)

### Inferences
- A pTMEnergy term in the user's loss addresses the *gradient-density* pathology of ipTM (single-position argmax) but is orthogonal to — and offers no help with — site specification. If anything, a denser interface-confidence gradient makes it *easier* for optimization to find a high-confidence interface anywhere on the target, so adding pTMEnergy without a site term can be expected to worsen off-epitope docking rather than improve it.
- Because pTMEnergy is a LogSumExp over inter-chain pairs ℐ, it is trivially restrictable to a hotspot subset: defining ℐ as binder×epitope pairs rather than binder×target pairs yields a site-specific pTMEnergy. The paper does not do this; it is an unexploited and directly implementable modification for the user's pipeline.

### Gaps
- The explicit form of the scaling kernel g(d_b) (presumably the TM-score kernel `1/(1+(d/d_0)^2)` with a length-dependent d_0) was not recovered verbatim.
- No peer-reviewed version found; arXiv preprint only.

## Cross-pipeline: does anyone put a SITE-SPECIFIC term into the SELECTION/filtering stage rather than only the gradient?

### Takeaway
Yes, and only two of the five do: **Germinal** (hard booleans `binder_near_hotspot`, `cdr3_hotspot_contacts > 0`, `percent_interface_cdr ≥ 0.5`, in both the post-hallucination and final filters) and **BindCraft2** (`Hotspot_Contact_Fraction`, `Epitope_Residues_Contacted`, `Off_Epitope_Contact_Fraction`, `Coldspot_Contact_Fraction` filter shortcuts). BindCraft 1, BindEnergyCraft and ColabDesign have no site-specific selection criterion at all; BindCraft 1's `Hotspot_RMSD` filter is a trajectory-consistency metric despite its name.

### Cited Findings

Additional cross-cutting findings:
- The only pipeline with **experimental** confirmation that its site enforcement works is Germinal: alanine mutagenesis at the specified hotspots reduced binding in 17/26 designs, and a cryo-EM structure retained contacts to the targeted I37/Y39/E41. **[summarized]** — [Germinal preprint v3](https://www.biorxiv.org/content/10.1101/2025.09.19.677421v3.full)
- BindCraft's epitope accuracy evidence is anecdotal/structural (3 crystal structures, 2 cryo-EM complexes, 2 competition assays) with no aggregate statistic. **[summarized]** — [BindCraft preprint](https://www.biorxiv.org/content/10.1101/2024.09.30.615802v1.full)
- BindEnergyCraft and EasyNano are computational-only. **[summarized]** — [BindEnergyCraft arXiv HTML](https://arxiv.org/html/2505.21241v1); [EasyNano arXiv HTML](https://arxiv.org/html/2606.12772v1)
- A related 2025 preprint reports that binder-design success rates "improved steadily as epitope size was narrowed," consistent with AF2 performance declining with system size — i.e. restricting the *target template* to epitope fragments is a third strategy, orthogonal to loss terms and filters. **I did not fetch this paper's full text; this is from a search snippet and should be verified before citing.** — [Discontinuous Epitope Fragments as Sufficient Target Templates for Efficient Binder Design, arXiv 2509.25479](https://arxiv.org/pdf/2509.25479)

### Inferences
- There are four distinct, independently combinable mechanisms for site enforcement across the published pipelines, and the user's pipeline currently implements only the first:
  1. **Attractive gradient term on epitope residues** — AfDesign/BindCraft/Germinal hotspot-masked `i_con` (distogram CCE, 14–22 Å cutoffs); EasyNano's ELU hinge at 8 Å. Weak and easily saturated at the cutoffs used.
  2. **Repulsive gradient term on non-epitope surface** — Germinal's `−λ·L_framework` (paratope side only); BindCraft2's `weights_coldspot_repel`/`weights_binder_coldspot` (off by default). No pipeline applies a general off-epitope repulsion on the *target* side at gradient time.
  3. **Input-space intervention** — BindCraft2 `forced_targeting` (Lys-scan the exposed target surface outside a 10 Å hotspot shell during early design, then restore); epitope-fragment-only templates. Requires no loss change and no gradient through a new term.
  4. **Hard site gate in selection** — Germinal's `binder_near_hotspot` boolean + `cdr3_hotspot_contacts > 0`; BindCraft2's `Epitope_Residues_Contacted` / `Off_Epitope_Contact_Fraction`.
- The published consensus, read across Germinal and BindCraft2, is that mechanism (4) is **not optional**: both pipelines retain the weak gradient term *and* add a hard geometric gate, and in Germinal's initial filter the site gate is the only thing checked besides clashes and shape complementarity — confidence metrics are deferred entirely to the external-predictor stage. The user's configuration (site pressure only in the gradient, selection on site-agnostic ipSAE) is the one combination that none of the surveyed pipelines uses.
- The weakest link in the user's current loss is likely the cutoff scale, not the weight. A contact term anchored on epitope residues at weight 0.5 is, if it follows the ColabDesign form, a distogram cross-entropy against sub-cutoff bins; at BindCraft/Germinal's 20 Å cutoff, a binder 14–27 Å away can be partially inside the cutoff for some epitope residues, so the term is already near its floor and provides little gradient toward the correct site. EasyNano's 8 Å ELU set-point and Germinal's 5.3 Å filter threshold bracket the scale at which "on-epitope" is actually being judged.

### Gaps
- No benchmark or review was found that directly compares these pipelines on **epitope specificity** as a metric. Each paper validates its own site accuracy with its own (mostly non-overlapping) assay, so no apples-to-apples off-epitope rate exists in the literature.
- No pipeline publishes the quantity the user most needs: the fraction of gradient-time-converged designs that dock off-epitope before filtering. Germinal's and BindCraft2's filter existence implies it is non-trivial, but the number is unpublished.
- BindCraft2's `i_pDAE` definition remains unknown (see earlier gap); if it is epitope-distance-masked it would be the only *site-aware ranking* metric in the field, which matters for the user's "retention ranks on site-agnostic confidence" problem.
